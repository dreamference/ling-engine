# Bugs and requests from SGLang's and vLLM's issue trackers

October 9, 2026 · a survey of 12 months of SGLang's and vLLM's GitHub issues (October 2025 to October 2026). It looks for bugs ling-engine must not repeat and for features its clients ask for. Performance techniques are out of scope; two other surveys cover them.

## Summary

1. **98 issues read in depth, out of 3,585 found.** 58 are vLLM's and 40 SGLang's. Each fixing pull request was identified (title and merge state); its description was read where the root cause was unclear. By kind: 61 correctness, 17 API, 10 performance, 10 hardware. For ling-engine the verdicts are 12 *yes* (the same bug is possible today), 42 *maybe* (possible under some condition, or not yet tested), and 44 *no*.

2. **The correctness classes that could hit ling-engine:**
   - **State corruption after a prefix hit.** This is the largest class on hybrid models, and it mostly shows up with speculation on. Output diverges after a cache hit, or degenerates into `!` (token 0). Examples: [vllm#60174](https://github.com/vllm-project/vllm/issues/60174), [vllm#55766](https://github.com/vllm-project/vllm/issues/55766), [sglang#41351](https://github.com/sgl-project/sglang/issues/41351). ling-engine's design (row invariance, commit by replay, chunking-independent prefill) answers it, and `--prefix-check` proves it offline bit for bit. Through the server, nothing tested it until now.
   - **NaN or inf logits turned silently into garbage.** Examples: [vllm#53305](https://github.com/vllm-project/vllm/issues/53305), [sglang#33187](https://github.com/sgl-project/sglang/issues/33187), and production's own FlashInfer bug. `Engine::sample` has no finiteness guard.
   - **Tool-call parsing of markup the model quotes:**
     - in code fences ([vllm#57541](https://github.com/vllm-project/vllm/issues/57541));
     - under names the request never offered ([vllm#58147](https://github.com/vllm-project/vllm/issues/58147));
     - as a literal `<tool_call>` before a real call ([vllm#56658](https://github.com/vllm-project/vllm/issues/56658));
     - with an unclosed middle parameter ([vllm#57699](https://github.com/vllm-project/vllm/issues/57699)).

     ling-serve's parser has all four.
   - **Penalty semantics.** `Engine::sample` applies presence and repetition penalties over the prompt as well as the output. Production SGLang counts output tokens only ([sglang#41124](https://github.com/sgl-project/sglang/issues/41124) is the same class).
   - **Stop strings in streams.** One bug was found while checking this class. Below a stop string's length, `Worker::generate` holds back output by *bytes*. That can split a UTF-8 character, and the JSON dump of the chunk then throws, which ends the stream with an error. Related: a stop string quoted inside the reasoning ends the turn ([sglang#40529](https://github.com/sgl-project/sglang/issues/40529)).

3. **The biggest API gaps** (details in [api-compat-checklist.md](api-compat-checklist.md)):
   - **Context overflow is not recognisable to any client.**
     - Codex compacts only on an in-stream `response.failed` with code `context_length_exceeded`. ling-serve sends `server_error`, so Codex retries the same prompt five times and never compacts.
     - LiteLLM (OpenHands) and Cline expect HTTP 400 and known message patterns. They get a 500.
   - **Codex's custom (freeform) tools are dropped** by the Responses conversion. This is the same as the SGLang code it mirrors.
   - **An image part is a 400.** Codex's model catalog advertises image input.
   - **Mid-stream chat errors** end without a finish chunk or `[DONE]`.
   - **reasoning_effort `none`** on chat completions is a 400.
   - **Invalid-JSON tool arguments** in a chat history make every later request of that conversation a 400.
   - **Silently ignored output controls:** `reasoning_tokens` is always 0, and `logprobs`, `n`, `response_format` and `tool_choice: required` are dropped without an error.

4. **Regression tests added** (section 3):
   - `tests/server/`: 49 HTTP test cases in 29 functions, following `bench/serve_smoke.py`'s way of reaching the server. 13 of the 49 are expected failures that state the right behaviour. Without a reachable ling-serve that names itself `ling-engine`, all of them skip. Checked here: they collect, and they skip with no server and against a stub that claims to be another engine.
   - `tests/api_tests.cpp`: 13 CPU cases. Six of them are `KNOWN(...)` gaps, which print but do not fail. **These were not compiled**: no builds run on this machine.

5. **The specification** gains section 18, *Known pitfalls*, and section 19, *Backlog from user requests* (since the split of 2026-10-09: `specs/DREAMFERENCE_LING_ENGINE_VALIDATION.md` and `specs/DREAMFERENCE_LING_ENGINE_BACKLOG.md`).

## 2. What could hit ling-engine

### 2.1 Hybrid state and prefix reuse

The largest class upstream, on both engines and almost always on Qwen3.5/3.6/3.8 hybrids. Typical reports:

| Symptom | Issues |
| --- | --- |
| Outputs change after a prefix hit, often only with speculation on | [vllm#60174](https://github.com/vllm-project/vllm/issues/60174), [vllm#53912](https://github.com/vllm-project/vllm/issues/53912), [vllm#43559](https://github.com/vllm-project/vllm/issues/43559) (−20% accuracy) |
| NaN from the first step when a prompt ends a few tokens past a block boundary | [vllm#55766](https://github.com/vllm-project/vllm/issues/55766) |
| A checkpoint attached to the wrong length | [sglang#38815](https://github.com/sgl-project/sglang/issues/38815) |
| An identical resend loses its hit | [sglang#22935](https://github.com/sgl-project/sglang/issues/22935) |
| Warm logits differ from cold ones because the prefill saw a different row count | [sglang#41351](https://github.com/sgl-project/sglang/issues/41351) |
| Drafter acceptance collapses to 0 after the first hit | [vllm#58894](https://github.com/vllm-project/vllm/issues/58894) |

**Why ling-engine's design answers it:**
- every kernel on the rows path is row-invariant;
- the DeltaNet state is committed by replay;
- a prompt's state does not depend on its chunking (M2 §4);
- `ling-run --prefix-check` proves resume against scratch bit for bit.

**What was untested:** the server path. That path covers a resend of the same prompt, prompt lengths of 2048·k + r with r ≤ 32 (the last chunk then takes the rows path), and a growing agent conversation with speculation on. Two tests now do this through HTTP:
- `test_prompt_length_near_chunk_boundary` (lengths 2049, 2079, 2080, 2081, 4112): cold, identical resend, and extension;
- `test_growing_conversation_warm_equals_cold`.

The drafter's own state after a hit is covered only indirectly, by the outputs. The acceptance check of [vllm#58894](https://github.com/vllm-project/vllm/issues/58894) belongs in the replay's `spec_report.py`.

### 2.2 NaN and degenerate output

Token 0 decodes as `!`, so NaN or uniform logits show up as `!!!!` until `max_tokens`. Examples:
- [vllm#53305](https://github.com/vllm-project/vllm/issues/53305) and [vllm#55291](https://github.com/vllm-project/vllm/issues/55291): Qwen3.5/3.6, persisting across requests;
- [sglang#36537](https://github.com/sgl-project/sglang/issues/36537): a kernel picked on SM12x;
- [sglang#33187](https://github.com/sgl-project/sglang/issues/33187): sanitising NaN into a uniform sample streams garbage as a healthy 200.

Production's FlashInfer bug was the same symptom.

**ling-engine today:**
- `Engine::sample` has no finiteness check. `max_element` over NaN is unordered, and `std::discrete_distribution` with NaN weights is undefined.
- Nothing stops a NaN state from being saved as a prefix checkpoint and then reused by every later session.

**What is needed:** a guard that ends the request with an error and a counter, and never saves a non-finite checkpoint (../specs/DREAMFERENCE_LING_ENGINE_VALIDATION.md §18).

**Tests:**
- `degenerate()` checks in the boundary, conversation, long non-English and untruncated-sampling tests;
- `test_untruncated_sampling_is_not_degenerate` repeats production's completions canary with `top_k` −1 and 0.

### 2.4 Sampling

**Penalties.** ling-engine penalises every prompt token. SGLang (production) counts output tokens only (checked in its `penaltylib`), and vLLM includes the prompt only for repetition. With Qwen's recommended presence penalty of 1.5 on a 25k-token agent context, every identifier in the context is penalised. Penalty requests also skip speculation.
- Test: `test_penalties_ignore_prompt_tokens`, expected to fail. At the first generated position a penalty must not change the token.

**Truncation under rejection sampling.** vLLM skipped `min_p` and `logit_bias` on verified tokens ([vllm#42744](https://github.com/vllm-project/vllm/issues/42744)). ling-engine builds the target p from the full chain, so it is not affected.
- Test: `test_truncation_to_one_token_equals_greedy`. At temperature 1, `top_k 1`, `min_p 1` and a tiny `top_p` must each equal greedy output, which exercises the accept path with a truncated target.

**Seeds** ([sglang#15481](https://github.com/sgl-project/sglang/issues/15481)): `test_seed_reproduces` checks both endpoints.

**Request validation** ([sglang#41482](https://github.com/sgl-project/sglang/issues/41482)): absurd values must leave the server healthy. One gap is noted but not tested, because the test would run long on a failure: a negative `max_tokens` currently means "unlimited".

### 2.5 Streaming, stop strings and cancellation

**The UTF-8 split (found here).** ling-engine's own bug. `Worker::generate` emits up to `all.size() − (longest stop − 1)` bytes, so with a stop list a multi-byte character can be cut in two. The chunk then fails `json::dump` (strict UTF-8), and the request ends with an error.
- It hits any streamed request with a stop list and non-ASCII output: Continue's autocomplete, and OpenHands' prompt-based tool fallback with `stop: ["</function"]`.
- Test: `test_streaming_with_stop_and_multibyte_text`, expected to fail.
- Fix: hold back to a character boundary.

**Stop strings in the reasoning.** They are matched over the raw text, so a stop string quoted in the reasoning ends the turn with empty content ([sglang#40529](https://github.com/sgl-project/sglang/issues/40529)). Decide against production's behaviour before changing it. No test yet.

**Cancellation.** The flag is checked once per emitted token. A request whose client left while it was queued or prefilling still runs its prefill, and the single worker makes everything wait ([sglang#36333](https://github.com/sgl-project/sglang/issues/36333)).
- Test: `test_disconnect_frees_the_engine` covers the decoding case.
- Backlog: check the flag between prefill chunks and before dequeuing.
