# ling-engine v0

v0 is the first working version: a C++20/CUDA engine that loads the production checkpoint as it is on
disk and serves it over the same HTTP API Mightling already calls. Mightling's agent, unmodified, runs
coding tasks against it. It exists to prove the stack end to
end:
- weights;
- every layer type;
- the tokenizer;
- the chat template;
- the API.

Each spec lever then lands on top of it and is measured against it. It is not yet faster than production:
it has none of the levers yet (no speculation, no CUDA graphs, no FP8 KV).

## What it is

| Part | v0 |
| --- | --- |
| Weights | Loaded straight from the safetensors checkpoint (`RadixArk/Qwen3.8-27B-NVFP4`): NVFP4 MLP and LM head, FP8 attention projections, BF16 norms and embeddings. Nothing is converted on disk; `ling-compile` comes later. |
| Decode kernels | Weight-streaming GEMVs that dequantize NVFP4 and FP8 in registers (M ≤ 8 rows). |
| Prefill | Chunks of 2048 tokens. Each matrix is dequantized to BF16 into one scratch buffer and multiplied on tensor cores with cuBLAS. |
| Gated DeltaNet | Causal conv (kernel 4) with carried state, gating, and the delta-rule recurrence with the state in registers (FP32). |
| Full attention | Gemma-style q/k norms, NeoX RoPE on 64 of 256 dims, output gate, BF16 KV cache. Decode: split-K over key ranges with an online softmax, one block per KV head serving its 6 query heads. Prefill: key/value tiles in shared memory shared by 48 query rows (CUDA cores). |
| Sampling | On the host: temperature, top-k, top-p, min-p, presence and repetition penalties; greedy at temperature 0. |
| Tokenizer | Byte-level BPE in C++. NFC through ICU, the pre-tokenizer pattern through PCRE2, added tokens matched first. Tested token for token against the reference tokenizer. |
| Chat template | The checkpoint's `chat_template.jinja` with production's two patches (medium as the default effort, `max`/`high` as xhigh, `minimal` as low; a later system message becomes a reminder), written out in C++: tools, tool calls, thinking on/off, `preserve_thinking`. |
| Server | `ling-serve` (proxygen), serving `GET /health`, `GET /v1/models` (with `max_model_len`), `GET /metrics` (empty for now), `POST /v1/responses` (what Mightling's agent calls), `POST /v1/chat/completions` and `POST /v1/completions`. All POST routes stream or not, with reasoning output and qwen3_coder tool calls typed by the request's tool schema. The Responses API is converted to chat as SGLang does: one leading system message, only `function` tools, effort `none` turns thinking off. |
| State | One sequence at a time. DeltaNet and conv state are snapshotted at the end of every prompt. A request whose prompt extends the previous prompt resumes from the snapshot, and one that extends everything processed so far resumes from the current state. An agent's next turn re-renders the model's output, so it always takes the first route. |

## Measured (8 October 2026, on the development Spark)

**Correctness:**
- **Kernels:** the NVFP4 and FP8 GEMVs match a host reference within 3e-5 at 1–8 rows. The BF16 cuBLAS path is within 1e-2 of the outputs' RMS.
- **Tokenizer:** identical to the reference on 300 of 300 texts (1,529,629 tokens). The corpus covers code, CJK, Arabic, Hindi, Cyrillic, emoji, special tokens and two source trees.
- **Chat template:** 84 of 84 renderings are byte-identical to the patched Jinja template.
- **Against production:** greedy output was checked against the production SGLang server on six prompts, 288 tokens. v0's token is SGLang's top-1 98.6% of the time and in its top 5 every time; the final build, with the prefill attention kernel and 2048-token chunks, gives 97.6% and 100% against a production-flag server (mean log-probability −0.192 under SGLang in both). The 1.4% are near-ties: SGLang also quantizes activations, v0 does not.
- **API:** `bench/serve_smoke.py` passes all checks:
  - health and models;
  - chat with the reasoning split;
  - streaming with usage;
  - tool calls with typed arguments, both non-streaming and streaming;
  - completions from token ids.
- **Mightling's agent end to end:** `puffin exec` pointed at ling-serve wrote and ran a primes script (53 s). In a second run it fixed a planted bug and ran pytest: 9 turns in 82 s, each turn after the first re-prefilling in ~0.7 s instead of 22 s.

**Speed, single stream.** Some runs shared the GPU with M0's SGLang experiments, so these are lower bounds.

| | v0 | Production (SGLang + DFlash2, M0's replay) |
| --- | --- | --- |
| Decode, short context | 10.5–11.8 tokens/s | — |
| Decode on agent work | ~10–11 tokens/s at 10K context | 47 tokens/s (4.95 tokens per 105 ms step) |
| Weight-streaming bandwidth | 236 GB/s NVFP4, 258 GB/s FP8 at M = 1 (bus: 262 GB/s) | 204 GB/s overall at M = 16 verify (NVFP4 208–225, FP8 in-projections ~218, FP8 out-projections 140; M0 report §5) |
| Prefill | ~690–720 tokens/s at 7.7K tokens (~440 on a cold 10K agent prompt before the prefill attention kernel and 2048-token chunks) | ~1,700 tokens/s |
| Next agent turn (10K-token session) | ~0.7 s to resume | — |
| Weights on the GPU | 20.2 GB, loaded in ~30 s | — |

v0 decodes one token per weight pass, about 85 ms. Production verifies about five tokens per pass, which explains its 4× lead. Speculation is lever 2 of the spec and the next thing to build on v0. Prefill is about 2.5× behind for two reasons:
- each 2048-token chunk dequantizes every weight to BF16 for cuBLAS;
- attention runs on CUDA cores, not tensor cores.

The spec's FP4 prefill (lever 3) replaces both.

## Not in v0

These are SPEC.md's levers and later milestones:
- speculation (DFlash2 drafter, context lookup);
- CUDA graphs;
- fused kernels;
- FP8 KV;
- GPU-side sampling;
- batching several sequences;
- shared-prefix DeltaNet checkpoints;
- images and video;
- `ling-compile`.

## Build (on the development Spark)

```bash
sudo apt install cmake ninja-build ccache nlohmann-json3-dev libpcre2-dev libicu-dev
# proxygen and its dependencies, once (about an hour): see SPEC.md §8
python3 build/fbcode_builder/getdeps.py build --no-tests --allow-system-packages \
    --scratch-path ~/ling-deps/scratch --install-prefix ~/ling-deps/proxygen proxygen   # in a proxygen checkout
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc
ninja -C build
./build/ling-kernel-tests
```

## Run

```bash
M=~/.cache/huggingface/hub/models--RadixArk--Qwen3.8-27B-NVFP4/snapshots/<rev>
./build/ling-run --model $M --chat "Write a haiku about memory bandwidth" --max-tokens 64
./build/ling-serve --model $M --port 8100 --served-model-name RadixArk/Qwen3.8-27B-NVFP4 --max-context 65536
```

## Checks

- **Kernels:** `ling-kernel-tests` compares the NVFP4 and FP8 GEMVs at every row count, and the dequantize-and-cuBLAS path, with a host reference.
- **Tokenizer:** `bench/tokenizer_test.py` compares `ling-tokenize` with the reference tokenizer on a multilingual corpus plus a source tree.
- **Forward pass:** `bench/validate_v0.py` generates greedily with `ling-run`, then teacher-forces the same tokens through the production SGLang server. It reports how often v0's token is SGLang's top-1 and top-5.
